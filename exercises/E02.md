## 0. Background and preparation

### 1.3. A better regex for email addresses

See if you can build a regex for the following rules? 

1. An email address must have a user part, an `@` sign, a domain, and optionally a `.` followed by a top-level domain.

2. User part: 
    1. The user part must start with a letter or digit.
    2. After its first character, the user part may contain letters, digits, dots (`.`), underscores (`_`), and/or hyphens (`-`).
    3. In general, the use part must be between 4-16 characters .

3. The `@` sign separates the user part from the domain.

4. Domain part: 
    1. The domain part must start with a letter or digit.
    2. After its first character, the domain part may contain letters, digits, underscores (`_`), and/or hyphens (`-`).
    3. The domain part can be between 1-256 characters.

5. The domain must be followed by a literal dot (`.`).

6. Top-level domain (tld) part 
    1. tld must contain at least two letters, but not more than 4 letters.
    2. Only upper case, lower case, digits, and `_` are alloed in tld.
    3. It is valid to not have tld, in which case the `.` after domain shall not be present.

```python
username = r"([A-Za-z0-9][A-Za-z0-9._-]{3,15})"
domain = r"([A-Za-z0-9][A-Za-z0-9_-]{0,255})"
```

**note** when we assemble `pattern`, we put `.` and tld in such a way that they have opening and closing parenthesis on the both side. We do this to ensure that `.` and tld appear (or dont appear) together. 

| Expression | explanation | 
|------------|-------------|
| [A-Za-z0-9]       | exactly one character which can be capital (A-Z), small (a-z) or digit (0-9) |
| [A-Za-z0-9._-]{3,15}         | capital, small, digit, '.', '_', or '-' repeated 3-15 times ({3,15})|
| [\w]{2,4}        | any word character (`\w`), repeated 2-4 times |


### 1.4. Extract named capture groups for email components and create structured data 

Create a dictionary entry for each domain where key is domain and values are all usernames in that domain. 

create **named capture groups** to store parsed data 

```python
username = r"(?P<name>[A-Za-z0-9][A-Za-z0-9._-]{3,15})"
domain = r"(?P<domain>[A-Za-z0-9][A-Za-z0-9_-]{1,255})"
tld = r"(?P<tld>[\w]{2,4})"

pattern = username + "@" + domain + r"(\." + tld + r")?" 
```

**`?P<name>`** creates a named capture group with the name given in `< >`. If a match occurs, it is stored in the respective named group. 

**use named groups to create data structure**

```python
user_dict = {}

for email in emails:
    match = re.fullmatch(pattern, email)
    if match:
        user_dict.setdefault(match.group('domain'), []).append(match.group('name'))
    else:
        print(f'invalid: {email}')
```

## 2. Processing web url/uri 

A URI is a web address that tells a program where a resource is and how to access it. each uri has some parts, like protocol, host, port, path etc. Each part has certain value. For example, in the following case, protocol's value is `https`, and query's value is `q=regex&page=2`

```text
https://example.com:8080/search?q=regex&page=2#results
```

- `protocol`: **https** tells the program which communication rules to use.
- `host`: **example.com** identifies the server that hosts the resource.
- `port`: **8080** is optional and identifies a specific service on that server.
- `path`: **/search** identifies a resource or location on the server.
- `query`: **q=regex&page=2** is optional and sends parameters to the resource.
- `fragment`: **results** is optional and identifies a location within the returned resource.

### 2.2. create regex for `protocol` 

`protocol` must be either `http` or `https`, followed by `://`, after which anything can occur. Please note that we only check protocol in this example, and do not verify rest of uri. That means, we accept everything which appears after protocol. 

- try writing this regex for a moment. When you are done with writing and executing your version, then see the following: 

```python
uri_pattern = (
    r"(?P<protocol>https?)://"
    r"(.*)"
)
```
This regex captures `http` or `https` as the named group `protocol`. Note the parenthesis of capture group `(?P<protocol>https?)` which means if a match occurs only `http` or `https` are stores, the remaining `://.*"` is not stored in `<protocol>`. `s?` makes the letter `s` optional. 

Also note that `.*` on second line says any character occuring zero oror more times after `://` is accepted. That means, after a valid protocol, it accepts everything.  

use your `uri_pattern `to validate your uris. 

```python
for uri in uris:
    match = re.fullmatch(uri_pattern, uri)
    if match:
        print('valid')
    else: 
        print('invalid')
```

### 2.3. create regex for `host` 

`host` must contain one or more letters, digits, dots, or hyphens.

Now we extend our `uri_pattern` to include `host` validation. 

```python
uri_pattern = (
    r"(?P<protocol>https?)://"
    r"(?P<host>[A-Za-z0-9.-]+)"
    r"([/:?#].*)?"
)
```

**note** that we have removed `r"(.*)"` after the `protocol`. Now regex for host `[A-Za-z0-9.-]+` captures one or more letters, digits, dots, or hyphens and stores them in `host` group. 

`r"([/:?#].*)?"` says immidiately after the host we have one of `[/:?#]` characters, followed by `.*` any character any number of times. The final `?` says the whole clause can occur `0` or `1` times, i.e. makes the whole clause optional.

### 2.4. create regex for `port`

`port` is optional. When present, it starts with `:` and contains one or more digits.

Now we extend our `uri_pattern` to include `port` validation. 

```python
uri_pattern = (
    r"(?P<protocol>https?)://"
    r"(?P<host>[A-Za-z0-9.-]+)"
    r"(:(?P<port>\d{1,5}))?"
    r"([/?#].*)?"
)
```

See the extended patter now includes regex for `port`. A port must start with `:`. After that a port can be a combination of 5 digits `(?P<port>\d{1,5})`, and if captured, it is stored in `<port>` group. The final `?` makes the entire `port` an optional part of uri. Finally, `r"([/?#].*)?"` accepts anything which, if, occurs after the port. Note that, it does not `:` now, which is already mentioned as a part of `port`, and cannot appear again in a valid uri.

### 2.5 create regex for `path` 

`path` is optional. When present, it starts with `/` and cannot contain whitespace, `?`, or `#`.


### 2.6. create regex for `query`

`query` is optional. When present, it starts with `?` and cannot contain whitespace or `#`.

```python
uri_pattern = (
    r"(?P<protocol>https?)://"
    r"(?P<host>[A-Za-z0-9.-]+)"
    r"(:(?P<port>\d{1,5}))?"
    r"(?P<path>/[^\s?#]*)?"
    r"(\?(?P<query>[^\s#]*))?"
    r"([#].*)?"
)
```
The query starts with `?`. Note the use of `\?`, which means literal match of `?`. If we do not escape `?` with `\` then `?` is treated as a quantifier.  After `?`, `query` can have any number of characters which are not white spaces or `#`

The captured query is stores in `query` group.
