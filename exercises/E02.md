## 0. Background and preparation

Regular expressions let a program search, validate, and extract parts of text that follow a pattern. They are useful when input such as email addresses or web addresses needs to be checked or broken into components.
In this exercise, we will build and refine simple patterns one step at a time. These patterns are for learning and are not complete implementations of the email or URL standards.

## 1. Parse email addresses

### 1.1 Start with a simple email pattern

We'll start with a simple regular expression for matching email addresses:

```regex
.+@.+
```

This accepts any string which contains an '@' with at least one character on each side.  

| Expression | Explanation |
|------------|-------------|
| .+         | `.` means any character, `+` quantifier means one or more times |
| @          | exact match with character `@` |
| .+         | `.` means any character, `+` quantifier means one or more times |

Here's some examples of valid and invalid email addresses:

```python
emails = [
    "ada.lovelace@chalmers.se",
    "student_42@example.com",
    "grace.hopper@chalmers.se",
    'a@c',
    "name@localhost",
    "missing-at-sign.example.com",
    "%ada@chalmers.se",
    "ada@.chalmers.se",
    '@',
    "mustafa.hassan@ucp.edu.pk"
]
```

Some results may change as the rules become more specific; for example, `name@localhost` is allowed by the final rules because the top-level domain is optional.

Now we can test our test data with our regular expression like so:


### 1.2. Create partial patterns and join

Break the regular expression into separate parts for username, domain, and top level domain (TLD):

```python
username = r"[^@\s]+"
domain = r"[^@\s_.]+"
tld = r"[^@\s_.]+"

pattern = username + "@" + domain + "." + tld 
```

**Note**: when `^` is used inside `[ ]`, it negates the pattern. For example `[^@\s]` means: _any character which is not `@` or a space (`\s`)_

### 1.3. A better regex for email addresses

Our current regex still accepts email addresses which start with %, &, # or other characters which we typically do not see in the start of email addresses.

See if you can **build a better regex with the following rules**:

1. An email address must have a user part, an `@` sign, a domain, and optionally a `.` followed by a top-level domain.

2. User part:
    1. The user part must start with a letter or digit.
    2. After its first character, the user part may contain letters, digits, dots (`.`), underscores (`_`), and/or hyphens (`-`).
    3. In general, the use part must be between 4-16 characters.

3. The `@` sign separates the user part from the domain.

4. Domain part:
    1. The domain part must start with a letter or digit.
    2. After its first character, the domain part may contain letters, digits, underscores (`_`), and/or hyphens (`-`).
    3. The domain part can be between 1-256 characters.

5. The domain must be followed by a literal dot (`.`).

6. Top-level domain (tld) part:
    1. tld must contain at least two letters, but not more than 4 letters.
    2. Only upper case, lower case, digits, and `_` are allowed.
    3. It is valid to not have tld, in which case the `.` after domain shall not be present.

First, give it a try yourself for a few minutes.
One possible solution is given below:

<details markdown="1">
<summary>Show solution</summary>

```python
username = r"[A-Za-z0-9][A-Za-z0-9._-]{3,15}"
domain = r"[A-Za-z0-9][A-Za-z0-9_-]{0,255}"
tld = r"[\w]{2,4}"

pattern = username + "@" + domain + r"(\." + tld + r")?" 
```

| Expression           | Explanation |
|----------------------|-------------|
| [A-Za-z0-9]          | exactly one character which can be uppercase (`A`-`Z`), lowercase (`a`-`z`) or a digit (`0`-`9`) |
| [A-Za-z0-9._-]{3,15} | capital, small, digit, `.`, `_`, or `-` repeated 3-15 times |
| [\w]{2,4}            | any word character (`\w`) repeated 2-4 times |

When we assemble `pattern`, we put `.` and tld in such a way that they are within parentheses, followed by `?`. We do this to ensure that `.` and tld appear (or don't appear) together.

</details>

### 1.4. Using named capture groups for extracting email components

In our regular expression we can also specify **named capture groups** to help us retrieve the various components of the parsed data. This might look like this:

```python
username = r"(?P<name>[A-Za-z0-9][A-Za-z0-9._-]{3,15})"
domain = r"(?P<domain>[A-Za-z0-9][A-Za-z0-9_-]{1,255})"
tld = r"(?P<tld>[\w]{2,4})"

pattern = username + "@" + domain + r"(\." + tld + r")?" 
```

where `?P<name>` creates a named capture group with the name given in `< >`, in this case `name`. If a match occurs, it is stored in the respective named group within the match object.

Once we have defined these groups, we can use them to build whatever data structure we need.
For example, **create a dictionary where keys are domains and values are all usernames in that domain:**

```python
user_dict = {}

for email in emails:
    match = re.fullmatch(pattern, email)
    if match:
        user_dict.setdefault(match.group('domain'), []).append(match.group('name'))
    else:
        print(f'invalid: {email}')
```

For the original examples above, the dictionary should look like this (the `domain` group does not include the optional top-level domain):

```python
{
    'chalmers': ['ada.lovelace', 'grace.hopper'],
    'example': ['student_42'],
    'localhost': ['name']
}
```

## 2. Processing web URLs

A URL is a web address that tells a program where a resource is and how to access it. Each URL is built up of various parts
For example, in the URL:

```text
https://example.com:8080/search?q=regex&page=2#results
```

we have:

- **protocol**: `https` tells the program which communication rules to use.
- **host**: `example.com` identifies the server that hosts the resource.
- **port**: `8080` is optional and identifies a specific service on that server.
- **path**: `/search` identifies a resource or location on the server.
- **query**: `q=regex&page=2` is optional and sends parameters to the resource.
- **fragment**: `results` is optional and identifies a location within the returned resource.

### 2.2. Create regex for protocol

The protocol must be either `http` or `https`, followed by `://`, after which anything can occur. Please note that we only check protocol in this example, and do not verify rest of URL. That means, we accept everything which appears after protocol.

**Try writing this regex yourself.**
When you are done with writing and executing your version, compare it with the following:

<details markdown="1">
<summary>Show solution</summary>

```python
url_pattern = (
    r"(?P<protocol>https?)://"
    r"(.*)"
)
```

This regex captures `http` or `https` as the named group `protocol`. Note the parenthesis of capture group `(?P<protocol>https?)` which means if a match occurs only `http` or `https` are stored, the remaining `://.*"` is not stored in `<protocol>`. `s?` makes the letter `s` optional.

Also note that `.*` on second line says any character occuring zero oror more times after `://` is accepted. That means, after a valid protocol, it accepts everything.  
</details>

### 2.3. Create regex for host

Host must contain one or more letters, digits, dots, or hyphens.
Now we extend our `url_pattern` to include `host` validation.

<details markdown="1">
<summary>Show solution</summary>

```python
url_pattern = (
    r"(?P<protocol>https?)://"
    r"(?P<host>[A-Za-z0-9.-]+)"
    r"([/:?#].*)?"
)
```

**Note** that we have removed `r"(.*)"` after the `protocol`. Now regex for host `[A-Za-z0-9.-]+` captures one or more letters, digits, dots, or hyphens and stores them in `host` group.

`r"([/:?#].*)?"` says immidiately after the host we have one of `[/:?#]` characters, followed by `.*` any character any number of times. The final `?` says the whole clause can occur `0` or `1` times, i.e. makes the whole clause optional.
</details>

### 2.4. Create regex for port

Port is optional. When present, it starts with `:` and contains one or more digits.
Now we extend our `url_pattern` to include `port` validation.

<details markdown="1">
<summary>Show solution</summary>

```python
url_pattern = (
    r"(?P<protocol>https?)://"
    r"(?P<host>[A-Za-z0-9.-]+)"
    r"(:(?P<port>\d{1,5}))?"
    r"([/?#].*)?"
)
```

See the extended patter now includes regex for `port`. A port must start with `:`. After that a port can be a combination of 5 digits `(?P<port>\d{1,5})`, and if captured, it is stored in `<port>` group. The final `?` makes the entire `port` an optional part of url. Finally, `r"([/?#].*)?"` accepts anything which, if, occurs after the port. Note that, it does not `:` now, which is already mentioned as a part of `port`, and cannot appear again in a valid url.
</details>

### 2.5 Create regex for path

Path is also optional. When present, it starts with `/` and cannot contain whitespace, `?`, or `#`.

<details markdown="1">
<summary>Show solution</summary>

```python
url_pattern = (

    r"(?P<host>[A-Za-z0-9.-]+)"
    r"(:(?P<port>\d{1,5}))?"
    r"(?P<path>/[^\s?#]*)?"

```

Path starts with `/` followed by 0 or more `*` characters which cannot contain whitespace `\s`, `?`, or `#`. Note the use of `^`, when it is placed inside `[ ]` it means negation.

### 2.6. Create regex for query

Query is also optional. When present, it starts with `?` and cannot contain whitespace or `#`.

<details markdown="1">
<summary>Show solution</summary>

```python
url_pattern = (
    r"(?P<protocol>https?)://"
    r"(?P<host>[A-Za-z0-9.-]+)"
    r"(:(?P<port>\d{1,5}))?"
    r"(?P<path>/[^\s?#]*)?"
    r"(\?(?P<query>[^\s#]*))?"
    r"([#].*)?"
)
```

The query starts with `?`. Note the use of `\?`, which means literal match of `?`. If we do not escape `?` with `\` then `?` is treated as a quantifier.  After `?`, `query` can have any number of characters which are not white spaces or `#`

The captured query is stores in `query` group.
</details>

### 2.7. Create regex for fragment

Fragment is optional. When present, it starts with `#` and cannot contain whitespace.
